# Repository Workflow & Branching Guidelines

## 1. Feature / Canonical Branches
* Все изменения и коммиты вносятся **исключительно в профильную каноничную ветку**, предназначенную для текущей задачи (например, `admin`, `ui`, `queue`, `schedule`, `infra` и др.).
* Пуш изменений выполняется только в эту ветку.

## 2. Preview Environment
* **Запрещен автоматический мердж в ветку `preview`.**
* Мердж в `preview` выполняется **только по прямому указанию пользователя** (например, «мерджи в превью») для ручной проверки и тестирования.

## 3. Production (`main`) Deployment
* **Запрещен автоматический мердж или пуш в ветку `main`.**
* Отправка в прод (`main`) выполняется **строго по отдельной подтверждающей команде пользователя** после успешной проверки функционала в ветке `preview`.
